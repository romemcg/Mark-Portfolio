The problem

Checking dozens of career pages by hand is slow, and good postings go stale within days. Being early matters.

My role

Product definition, filters and rules, and the agent's instructions.

Product decisions

  • Read only agent. It adds rows and never acts on my behalf, because an automated application can cost a real opportunity.
  • Rules written as instructions, not guessed. Blockers are explicit.
  • A human sets status. The agent never changes a status I set.

Challenges and what I learned

  • Duplicates and stale postings across sources.
  • Fit ratings are a rough guide, not a verdict, and I treat them that way.

Results

  • A working tracker that refreshes every weekday.

1. Overview

A tracker of live job openings and career portals across the UAE and Oman. A scheduled AI agent runs each weekday, finds new postings, applies my rules and records them in a shared database with a fit rating. It only adds information. It never applies, never messages anyone and never changes a status that I set.

2. Goals and non goals

Goals

  • Surface new relevant roles within a weekday of publication.
  • Remove roles that cannot work for me before I see them.
  • Give each opening a fit rating so I can decide where to spend effort.
  • Keep me in control of every action.

Non goals

  • No automated applications and no automated messages.
  • No replacement for networking or direct outreach.
  • No claim that a fit rating predicts an offer.

3. Users and needs

Me, during an active job search

Stop checking dozens of career pages by hand and stop missing fresh postings.

4. User stories

  • As a job seeker, I want new postings recorded every weekday, so that I act on fresh roles first.
  • As a job seeker, I want my hard blockers applied automatically, so that I never review a role that cannot work.
  • As a job seeker, I want to set my own status on each role, so that the agent never overwrites my decisions.

5. Functional requirements

P0 is required for the first release. P1 follows. P2 needs evidence first.

R1P0

Weekday agent run

A scheduled agent searches job sources and portals each weekday.

Acceptance: New postings appear as rows with a source link and posting date.

R2P0

Hard blocker filters

My own blockers are written into the agent's instructions as rules.

Acceptance: Roles that match a blocker are not recorded as openings.

R3P0

Fit rating

Each opening gets a rating against my profile.

Acceptance: The rating is stored with the row and treated as a guide, not a verdict.

R4P0

Human controlled status

A status field I can change on every row.

Acceptance: The agent never changes a status I set.

R5P0

No autonomous actions

The agent can read and record only.

Acceptance: It never applies to a job and never sends a message to anyone.

R6P1

Career portal tracker

A list of employer career portals across the UAE and Oman.

Acceptance: Each portal is checked as part of the weekday run.

R7P1

Freshness view

Newest postings first, with age shown on each row.

Acceptance: Stale postings are easy to see and ignore.

R8P2

Outcome review

Link radar finds to applications and outcomes.

Acceptance: I can see how many applications started from a radar find.

6. Non functional requirements

Safety
Read and record permissions only, written as explicit hard limits in the instructions.
Auditability
Every row keeps its source link and the date it was first seen.
Reliability
The agent follows the same rules every run, so results are comparable day to day.
Privacy
The database and profile are private to me.

7. Scope

In scope

  • Weekday scheduled search
  • Blocker filters and fit rating
  • Shared database with a status I control

Out of scope

  • Applying or messaging on my behalf
  • Public access
  • Any claim of predicting outcomes

10. Risks and mitigations

Duplicate or stale postings across sources.

Mitigation: Record the source and first seen date, and match on title and company.

Ratings give false confidence.

Mitigation: Label them as a guide and review every row myself.

An agent acts on my behalf by mistake.

Mitigation: Explicit hard limits and read only permissions.

11. Open questions

  • Which sources produce the most roles I actually pursue?

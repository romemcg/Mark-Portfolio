Smart City Intelligence Hub

A free, interactive platform that maps the smart city and IoT ecosystem as one connected knowledge graph.

The problem

Information in smart cities and IoT is fragmented. MQTT is explained in one place, digital twins in another and smart buildings somewhere else, so it is hard to see how it all connects. Newcomers do not know where to start, and practitioners rarely get one place that links protocols, subsystems, use cases and real deployments.

My role

Product owner, designer and builder. I defined the content model, wrote the explanations, designed the navigation and built the site with AI assisted development.

Product decisions

  • Learning paths over a flat library. A visitor who does not know what to open first leaves, so the home page asks who they are.
  • The graph is a primary view, not a decoration. The point of the product is the connections.
  • Free and open. It started as my own learning tool and works best when practitioners can test and correct it.

Challenges and what I learned

  • Keeping depth consistent across 22+ protocols and 18+ use cases. A content template for each type kept entries comparable.
  • Making a dense graph readable. Grouping and filtering matter more than adding more nodes.
  • Accuracy. I am a practitioner, not a reference publisher, so feedback from other practitioners is the quality check.

Results

  • Started as a personal learning tool. I now use it for research, client conversations and solution design.

1. Overview

A free reference platform that explains the smart city and IoT ecosystem as one connected system. It combines a protocol library, subsystem guides, use cases, reference architectures, global deployments, career paths and interview preparation, and ties them together with an interactive knowledge graph so a reader can follow connections instead of reading isolated definitions.

2. Goals and non goals

Goals

  • A complete beginner can build a working mental model of a smart city in one sitting.
  • A practitioner can find a protocol, subsystem, use case or architecture and see what it connects to within a minute.
  • Content is accurate and consistent enough to use in research, client conversations and solution design.
  • The platform stays free to use and easy to extend as practitioners ask for more.

Non goals

  • Not a vendor directory or product comparison site.
  • Not a news feed. Content is structured reference material.
  • Not a replacement for standards documents or vendor documentation.

3. Users and needs

Complete beginner

Fundamentals first, in plain language, then a way to see which careers and use cases exist.

IoT technical

Protocol depth, subsystem architecture and enterprise reference patterns.

Product manager

Use cases with KPIs and ROI, market intelligence, career roadmaps and interview preparation.

Global projects analyst

Real deployments with transferable lessons and strategic perspective.

4. User stories

  • As a beginner, I want to be told where to start, so that I do not get lost in 150+ linked concepts.
  • As an engineer, I want a protocol explained with an analogy and then in technical depth, so that I can teach it to others and still trust the detail.
  • As a product manager, I want each use case to state the problem, architecture, KPIs and ROI, so that I can reuse it in a business case.
  • As a practitioner, I want to click a concept in the knowledge graph and see everything it relates to, so that I understand dependencies before designing a solution.
  • As a career changer, I want a 30, 60 and 90 day plan for a role, so that I know what to learn in what order.

5. Functional requirements

P0 is required for the first release. P1 follows. P2 needs evidence first.

H1P0

Guided starting paths

The home page offers four starting paths: Complete Beginner, IoT Technical, Product Manager and Global Projects.

Acceptance: Each path leads to a relevant first page, and the home page shows the platform's coverage at a glance.

H2P0

Protocol library

22+ IoT protocols, from MQTT and CoAP to LoRaWAN and NB-IoT, each with a plain language analogy before technical depth.

Acceptance: Every entry carries a category such as application layer, LPWAN or cellular, and an everyday explanation.

H3P0

Subsystem guides

10+ core smart city subsystems such as BMS, SCADA and GIS, and how they interact.

Acceptance: Each subsystem links to the protocols and use cases that depend on it.

H4P0

Use case library

18+ real smart city use cases such as smart parking, waste management and street lighting.

Acceptance: Each use case states the problem, the technologies involved, the architecture and the ROI.

H5P0

Interactive knowledge graph

A graph of 150+ linked concepts built with React Flow.

Acceptance: Selecting a node shows its relationships, and links from a node open the matching page.

H6P1

Solution architectures

18+ solution architectures with KPIs and implementation notes.

Acceptance: Every architecture lists components, data flow and measurable KPIs.

H7P1

Global deployments

10 deployments from Singapore to NEOM, including Dubai, Barcelona, Amsterdam, Seoul and Masdar City.

Acceptance: Each case states what was built and the lessons that transfer to other cities.

H8P1

Career, market and interview sections

5 career paths with 30, 60 and 90 day plans, a market view, product manager interview preparation and a glossary.

Acceptance: Each career path has a dated plan, and glossary terms link back to the concept pages.

H9P2

Practitioner feedback loop

A simple way for practitioners to correct content and request additions.

Acceptance: Requests are recorded and drive the next content release.

6. Non functional requirements

Responsive
Works on phone, tablet and desktop. The sidebar collapses to give content more room.
Theming
Light and dark theme toggle.
Consistency
A content template per entry type keeps depth comparable across protocols, use cases and architectures.
Performance
Mostly static content on a Next.js stack so pages load quickly.
Maintainability
Content is structured data, so adding a protocol or use case does not need a redesign.

7. Scope

In scope

  • Reference content, learning paths and the knowledge graph
  • Career and interview material for smart city and product roles
  • Free access for learners and practitioners

Out of scope

  • Vendor comparisons and sales content
  • News and commentary
  • Paid tiers or gated content
  • User generated content in the first release

10. Risks and mitigations

Factual errors, because I am a practitioner and not a reference publisher.

Mitigation: Practitioner review and a visible way to report corrections.

Uneven depth across 150+ concepts.

Mitigation: A content template for each entry type.

The graph becomes unreadable as it grows.

Mitigation: Grouping and filtering before adding more nodes.

Content goes stale as deployments and standards change.

Mitigation: Date sensitive entries and review them on a schedule.
